# 部署补丁：release-r13b（动态预算+深度版新霸王，供实测）

> 分支：`ai/rel-r11`（基于 **main = 线上 2026.10.22-845ec5 线**，带预想接口）
> 默认 = **r13b 动态档**（开局不变慢：1–5 回合 3000ms/depth7；6–13 回合升到 6000ms/depth8；节点制跳过）；**未合并 main**，等用户实测拍板。

## 0. 线上真实基准（先看）
- 线上 `LEVELS.hard = { budget: 3000, dyn: 2.7 }` → 平时≈3s/步，难局最多≈8.1s；`xhard`=9000。
- 本补丁默认 r13b 动态曲线：**1–5 回合 3000ms / depth7（和现在一样快、一样深）**；6–13 回合预算线性升到 **6000ms（2.0×）**、depth 升到 **8**；≥13 回合维持 6000ms/depth8。
- 动态档**关掉原 dyn 的 2.7× 再放大**（曲线本身承担“难局多想”）；最坏单步实测约 **12.6s**（第 3 层 2× 兜底 + 深度迭代），平均远低于上限。

## 1. 改了什么
1. `source/src/bfai.js`（默认 = r13b 动态版）：
   - **保留 main 全部能力**：预想接口（ponderStart/Move/Stop/Info）、MCAP、T6、TTD、BMH、PVS、SPEND、C70/C71/C72；
   - **r11 五项修法**：CAPTIE / SPD / PUPD / UPQ / DPNT + 打开 r4 系开关（ATKUP/CAPUP/UP3L/CAPUP2）；
   - **r13b 动态预算+深度**（BFAI_DYN2）：回合 1–5 = 3000/depth7；6→13 预算→6000、depth→8；复杂度修正（残子≤20/军功和≥30/有 lv≥3 子各 +4%，封顶 ×1.12）；节点制整段跳过。
2. 备用档（`source/docs/deploy/rel-r11/`，覆盖 `source/src/bfai.js` 后 `node build.js` 即切换）：
   - `bfai-p4500.js`：**静态 4500ms + 原 dyn**（= 实测 63.8% 的 P45 档，“最强但开局也慢/难局会放大”）
   - `bfai-p6500.js`：静态 6500ms（2.17×，等效 r12 后段上限）
   - `bfai-r11s.js`：静态 6500 + 提速 getter ×1.48（≈9620ms，最慢档）
   - `bfai-xian.js`：**兵仙（xhard）动态版骨架 —— 待兵仙实测数据确认，先别作为默认**。
     行为：兵仙档也走与霸王同一套动态曲线（基础 9000ms → 6→13 回合升到 18000ms，depth 7→8），
     开局不慢于线上原生 9s；预想接口保留；节点制（考卷）跳过。
     现状：默认 `bfai.js` 的动态曲线**只作用于霸王（hard）**，兵仙 xhard 保持线上原生行为；
     等兵仙 ×3/×4 对打数据确认收益后，再决定是否把 `bfai-xian.js` 设为默认或调成 ×4/更深参数。
   - 默认档 r13b 的胜率/曲线见下。

## 2. 实测数据（生产口径：vs 线上原样 3000ms，600 局/档，0 出错）
| 档位 | 得分 | 95% CI | 执汉 | 执楚 | 均节点/步 | 均耗时/步 | 说明 |
|---|---|---|---|---|---|---|---|
| P30 同 3000ms（纯 AI 增量） | 57.0% | 53.1–60.9 | 62.0% | 51.8% | 119,402 | 4.69s | 不牺牲速度 |
| P45 静态 4500（+原 dyn） | **63.8%** | 60.1–67.6 | 72.0% | 55.3% | 141,788 | 5.64s | 最高分，但开局也慢、难局会放大 |
| r12 动态仅时间（depth7） | 59.0% | 55.2–62.8 | 65.7% | 52.0% | 119,625 | 4.63s | 被 depth7 抵消 |
| r13 动态预算+深度 | 61.3% | 57.4–65.1 | 67.3% | 55.0% | 146,972 | 5.28s | 上限 6500/depth9 |
| **r13b 动态（默认档）** | **62.3%** | 58.4–66.1 | 69.0% | 55.3% | 125,458 | 5.07s | **开局快、后段 6s、性价比最好** |
| r13c 动态+难局 dyn 放大 | 60.5% | 56.6–64.4 | 68.7% | 52.3% | 155,277 | 5.53s | 更慢但分更低，不采用 |
- 结论：**r13b（默认）= 62.3%，在 60–65 目标区间内；开局与现线上一样快、平均 5.07s/步**（比 P45 的 5.64s 便宜）；P45 最高分 63.8% 但开局也慢、难局可能更久。
- r13b 实测曲线（自对弈 2 局）：开局(1–5) **3.40/3.32s**（max 6.05）；中局(6–10) 3.80/3.54s；中后(11–16) 6.08/4.69s；后段(17+) 7.07/5.85s（**max 12.6s**）。
- 认证线（对 r1 同条件）仍 <60%（A 48.8% / 65 组 49.8%），对外口径只写“对现线上”。

## 5. 预想接口 / maxMs
- 预想实现在 `bfai.js`（ponderStart/Move/Stop/Info + think 的 opt.ctl）；main.js 只接线。
- 动态只改 `L.budget/L.depth`；预想期间 ctl 覆盖 deadline/nodeCap（动态放大对预想无效，安全）。
- 普通人机不传 maxMs，动态 6000 不会被砍；开计时/联机替补 AI 时按钟保护（main.js 原逻辑），属期望行为。
