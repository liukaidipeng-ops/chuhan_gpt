# 部署补丁：release-r16（默认档 = r15 + T5 漏着窄修，供实测）

> 分支：`ai/rel-r11`（基于 **main = 线上 2026.10.22-845ec5 线**，带预想接口）
> 默认 = **r16**：r15（r13b + 背水 UX 修复）+ **T5 漏着窄修**；**未合并 main**，等用户实测拍板。
> 云批生产口径（vs 线上原样 3000ms，600 局）：**r16 = 63.6%（95% 59.7–67.5）**，执汉 69.7% / 执楚 57.3%，平均 4.92s/步；
> **同批直接对打 r16 vs r15（同基底，唯一差异=T5 窄修）600 局 = 48.4%（45.6–51.2，CI 含 50）→ 只修 T5、整体强度不变**。
> 本次修复对象：用户反馈的“过河兵不处理”漏着（issue25 第5回合、2026-10-26 新局第5回合）——不靠全局加时间/加深度换胜率（**对外只写“T5 漏着修复 + 强度不变”**）。

## 0. 线上真实基准（先看）
- 线上 `LEVELS.hard = { budget: 3000, dyn: 2.7 }` → 平时≈3s/步，难局最多≈8.1s；`xhard`=9000。
- 默认 r16 保留 r13b 动态曲线：**1–5 回合 3000ms / depth7**；6–13 回合预算线性升到 **6000ms（2.0×）**、depth 升到 **8**；≥13 维持 6000ms/depth8；关掉原 dyn 2.7× 再放大。
- **r16 只新增 T5 窄修**（时间制、霸王档）：**第 5–7 回合**、敌 lv≥2 兵进我方半场且**距帅 6–7** → 该手预算 ×2（封顶 6000，不砍基础）+ 迭代加深至少跑到 **depth5**；**无全局评估项、无 ALLOW 改动、其它局面与 r15 完全一致**。
- 背水 UX（r15 起）：被迫解将时对每个解将组合深搜 4 层（合 6 层）+ 冻结罚分（帅/将 −1.5、车 −0.8、炮/马 −0.3、士/象/兵 −0.1）；常规用背水分支同样减冻结罚分。

## 1. 改了什么
1. `source/src/bfai.js`（默认 = r16，**自包含合并版**：main + r11 五项 + r13b 动态 + r15 背水 + r16 T5 窄修）：
   - **保留 main 全部能力**：预想接口（ponderStart/Move/Stop/Info）、MCAP、T6、TTD、BMH、PVS、SPEND、C70/C71/C72；
   - **r11 五项修法**：CAPTIE / SPD / PUPD / UPQ / DPNT + r4 系开关；
   - **r13b 动态预算+深度**（BFAI_DYN2）：回合 1–5 = 3000/depth7；6→13 预算→6000、depth→8；节点制（考卷）整段跳过；
   - **r15 背水 UX**：`FREEZE_W`/`freezeCost()` + 被迫解将深搜择优 + 常规分支冻结罚分；`TR.artAll/artPick` 输出供单测；
   - **r16 T5 窄修**（BFAI_R16）：窄触发 ×2 预算封顶 6000 + 保证 depth5；触发面仅“第5–7回合、敌 lv≥2 兵距帅6–7”，其余与 r15 相同。
2. 备用档（`source/docs/deploy/rel-r11/`，覆盖 `source/src/bfai.js` 后 `node build.js` 即切换）：
   - `bfai-r15.js`：**上一默认档**（云 64.9%，背水 UX，无 T5 修）
   - `bfai-r13b.js`：更早默认档（云 62.3%）
   - `bfai-r14.js`：r14 实验版（云 60.2%，体感回归，已回退，仅记录）
   - `bfai-r16.js`：= 本默认档原始副本
   - `bfai-p4500.js` / `bfai-p6500.js` / `bfai-r11s.js`：静态时间档（历史实验）
   - `bfai-xian.js`：兵仙（xhard）动态版骨架（默认 xhard 仍线上原生行为）

## 3. 怎么拉下来实测
```bash
git fetch origin
git checkout ai/rel-r11
cd source
npm ci
node build.js
npx serve ..      # 打开仓库根 index.html
```
人机对战 → 霸王：开局≈3s；**第 5–7 回合若汉兵刚过河、离帅 6–7 格，电脑会多花约 2–3s 算“吃/挡该兵”**（避免走闲车/闲兵）；中后段复杂局面 4–6s；遇到“被将军、只能背水解”时优先选“不冻帅/小代价”的两步组合。

## 5. 预想接口 / maxMs
- 预想实现在 `bfai.js`（ponderStart/Move/Stop/Info + think 的 opt.ctl）；main.js 只接线。
- 动态/背水/T5 窄修只改 `L.budget/L.depth` 与背水候选选择；预想期间 ctl 覆盖 deadline/nodeCap。
- 普通人机不传 maxMs，动态不会被砍；开计时/联机替补 AI 时按钟保护（main.js 原逻辑）。
- 本分支另含 main.js“复制对局文本”兜底修复（浏览器拦截自动复制时弹导出框），只影响 UI。
