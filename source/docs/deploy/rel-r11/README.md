> 分支：`ai/rel-r11`（基于 **main = 线上 2026.10.22-845ec5 线**，带预想接口）
> 默认 = **r14 动态档**（开局不变慢；危险兵局面自动加权/加深；节点制跳过）；**未合并 main**，等用户实测拍板。
> 本版重点修 **issue25（用户真局 25 回合将死旧预览版）**：汉兵刚过河、距帅 6 时旧版 3s 只搜到 depth4、把“顶住该兵”低估排到第 16；r14 在时间制下把危险兵局面强制跑到 depth5 + 静态威胁项 + 预警半径 3→7，已复现“该走 兵6,6→6,5×兵”。

## 0. 线上真实基准（先看）
- 线上 `LEVELS.hard = { budget: 3000, dyn: 2.7 }` → 平时≈3s/步，难局最多≈8.1s；`xhard`=9000。
- 默认 r14 动态曲线：**1–5 回合 3000ms / depth7（和现在一样快、一样深）**；6–13 回合预算线性升到 **6000ms（2.0×）**、depth 升到 **8**；≥13 维持 6000ms/depth8。
- r14 新增（只时间制）：危险兵（敌 lv≥2 兵进我方半场、距帅 ≤7，第5回合起）→ 迭代加深保证跑到 depth5；预算窄档 ×2.0、早段≥6000ms（只放大不砍基础）；慢机兜底对“吃/贴该兵”候选单独补算 depth5；静态评估加“兵逼近帅”威胁项。
- **最坏单步实测 ≈12.1s**（不高于 r13b 的 12.6s）；平均：开局 2.3–3.2s、中局 4.2–4.3s、后段 5.4–8.2s（仅危险局面拉长）。
- 动态档关掉原 dyn 2.7× 再放大（曲线/危险档本身承担“难局多想”）。

## 1. 改了什么
1. `source/src/bfai.js`（默认 = r14 动态版）：
   - **保留 main 全部能力**：预想接口（ponderStart/Move/Stop/Info）、MCAP、T6、TTD、BMH、PVS、SPEND、C70/C71/C72；
   - **r11 五项修法**：CAPTIE / SPD / PUPD / UPQ / DPNT + 打开 r4 系开关；
   - **r13b/r14 动态预算+深度**（BFAI_DYN2/BFAI_R14）：回合 1–5 = 3000/depth7；6→13 预算→6000、depth→8；危险兵局面再加“depth5 保证 + 威胁项 + 预警提前”；**节点制（考卷）整段跳过**。
2. 备用档（`source/docs/deploy/rel-r11/`，覆盖 `source/src/bfai.js` 后 `node build.js` 即切换）：
   - `bfai-p4500.js`：**静态 4500ms + 原 dyn**（= 实测 63.8% 的 P45 档）
   - `bfai-p6500.js`：静态 6500ms（2.17×）
   - `bfai-r11s.js`：静态 6500 + 提速 getter ×1.48（≈9620ms，最慢档）
   - `bfai-xian.js`：**兵仙（xhard）动态版骨架 —— 待兵仙实测数据确认**（基础 9000→后段 18000，depth 7→8；默认档的 xhard 仍保持线上原生行为）
   - 默认档 r14 的胜率/曲线见下。

## 5. 预想接口 / maxMs
- 预想实现在 `bfai.js`（ponderStart/Move/Stop/Info + think 的 opt.ctl）；main.js 只接线。
- 动态/危险修法只改 `L.budget/L.depth`；预想期间 ctl 覆盖 deadline/nodeCap。
- 普通人机不传 maxMs，动态不会被砍；开计时/联机替补 AI 时按钟保护（main.js 原逻辑）。
- 本分支另含 main.js“复制对局文本”兜底修复（浏览器拦截自动复制时弹导出框），只影响 UI，不影响引擎。
