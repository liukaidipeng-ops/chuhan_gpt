## 0. 修的是什么（根因）

同一局面、同一 250k 节点预算：

| 局面 | 仓库现用引擎（无实验室升级枚举） | 实验室 r17b |
|---|---|---|
| 2026-11-05 局 T13（at=30） | **d5**，+9.363（选 `车1,1→2,1`） | d3，**+16.390**（选 `车×车`），6.0s |
| 同局 T14（at=33） | d3，38 个根候选**全 −8996（必败）** | d3，**+12.330**（选 `车吃相`），9.8s |

实验室引擎在危险局面里，每个根候选都拖着“免费升级组合”（根上多给的升级候选 + 搜索第 2 层 UP2 / 对方第 3 层 ALLOW/UP3L），分支爆炸 → **有效深度只有 3 层**（实测 `nodes:4000000` 跑 99 秒、`time:15000` 跑 41 秒都仍只到 depth3）→ 把“五步后被贴脸杀”读成 +12 大优。

## 1. 改了什么

1. `source/src/bfai.js`（默认 = r19）：r17b + 危险兵窄修
   - 触发（**仅时间制·霸王档**；节点制/考卷整段跳过）：敌 lv≥2 兵距我帅 Manhattan ≤3，或敌 lv≥4 兵距帅 ≤4（神速营两格跳）；**任意回合**。
   - ① 搜索第 2/3 层“先升级再走”枚举整段关掉（只保留 ply1 的“对方先升级再走”）——与仓库现用引擎形状一致；
   - ② 根上升级候选只留静态收益最好的 1 个（`must` 全留）；
   - ③ 危险局面把 dyn/DYN2 放宽出来的预算收回基础档（省下的时间换成更深一层），根上近并列优先“解决危险兵”。
   - 不改估值、不加全局威胁项、不做全局加深。
2. 备用档（`source/docs/deploy/rel-r11/`）：
   - `bfai-r17b.js`：上一默认档（103745B / `CDC16EB9…`；与 `bfai-r17.js` 同一份）
   - `bfai-r16.js`（102291B / `0C7D353A…`）、`bfai-r15.js`（64.9%）、`bfai-r13b.js`（62.3%）、`bfai-r14.js`/p4500/p6500/r11s/bfai-xian 全保留
3. **UI 导出校验**（同分支 main.js，早前 commit）：`exportGame` 写 `o.base` 前本地重放校验，base 被污染时省略 base 并标 `baseIgnored:true`（用户 2026-10-27 29 回合局无法回放的根因修复）。本版**未改动**。
