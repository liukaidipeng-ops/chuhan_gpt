# 部署补丁：release-r15（默认档 = r13b + 背水 UX 修复，供实测）

> 分支：`ai/rel-r11`（基于 **main = 线上 2026.10.22-845ec5 线**，带预想接口）
> 默认 = **r15**：r13b 默认档 + **背水一战（主帅兵法）选出修复**；**未合并 main**，等用户实测拍板。
> 云批生产口径（vs 线上原样 3000ms，600 局）：**r15 = 64.9%（95% 61.1–68.8）**，执汉 69.3% / 执楚 60.3%，平均 4.88s/步；r13b 62.3%、P45 63.8% → **目前最强生产口径候选**（注意：与 r13b 是不同种子组，直接对打 131000/132000 在跑，作补强证据）。
> 本次重点：修用户明确抱怨的“背水用得蠢”（issue25 第24回合，升相+背水把将也挪走、白丢子）——不是靠加时间/加深度换胜率（不对外写“强度 +6.5”）。

## 0. 线上真实基准（先看）
- 线上 `LEVELS.hard = { budget: 3000, dyn: 2.7 }` → 平时≈3s/步，难局最多≈8.1s；`xhard`=9000。
- 默认 r15 保留 r13b 动态曲线：**1–5 回合 3000ms / depth7**；6–13 回合预算线性升到 **6000ms（2.0×）**、depth 升到 **8**；≥13 维持 6000ms/depth8；关掉原 dyn 2.7× 再放大（曲线本身承担“难局多想”）。
- r15 只改**背水一战的选择**（楚方、每局最多一次、触发极少）：普通走法为 0（只能用背水解将）时，对每个解将组合**深搜 4 层（合 6 层）+ 冻结罚分**（帅/将 −1.5、车 −0.8、炮/马 −0.3、士/象/兵 −0.1）取最优；常规用背水分支同样减冻结罚分。汉方代码/评估/预算/深度/根候选生成**零改动**。

## 1. 改了什么
1. `source/src/bfai.js`（默认 = r15）：
   - **保留 main 全部能力**：预想接口（ponderStart/Move/Stop/Info）、MCAP、T6、TTD、BMH、PVS、SPEND、C70/C71/C72；
   - **r11 五项修法**：CAPTIE / SPD / PUPD / UPQ / DPNT + r4 系开关（ATKUP/CAPUP/UP3L/CAPUP2）；
   - **r13b 动态预算+深度**（BFAI_DYN2）：回合 1–5 = 3000/depth7；6→13 预算→6000、depth→8；节点制（考卷）整段跳过；
   - **r15 背水修复**：`FREEZE_W`/`freezeCost()` + 被迫解将深搜择优 + 常规分支冻结罚分；`TR.artAll/artPick` 输出供单测。
2. 备用档（`source/docs/deploy/rel-r11/`，覆盖 `source/src/bfai.js` 后 `node build.js` 即切换）：
   - `bfai-r13b.js`：**上一默认档（云 62.3%，最稳）**
   - `bfai-r14.js`：r14 实验版（云 60.2%，体感回归，已回退，仅记录）
   - `bfai-r15.js`：= 本默认档的原始副本（便于切换/回滚）
   - `bfai-p4500.js`：静态 4500ms + 原 dyn（实测 63.8%）
   - `bfai-p6500.js`：静态 6500ms（2.17×）
   - `bfai-r11s.js`：静态 6500 + 提速 getter ×1.48（≈9620ms，最慢档）
   - `bfai-xian.js`：兵仙（xhard）动态版骨架（基础 9000→后段 18000；默认 xhard 仍线上原生行为，待兵仙数据）

## 3. 怎么拉下来实测
```bash
git fetch origin
git checkout ai/rel-r11
cd source
npm ci
node build.js
npx serve ..      # 打开仓库根 index.html
```
人机对战 → 霸王：开局应与现在一样快（≈3s）；中后段复杂局面 4–6s；**遇到“被将军、只能背水解”的局面**，电脑应优先选“只冻结小代价子/不冻帅”的两步组合，不再乱动将。可直接用 issue25 第24回合场景体验。

## 5. 预想接口 / maxMs
- 预想实现在 `bfai.js`（ponderStart/Move/Stop/Info + think 的 opt.ctl）；main.js 只接线。
- 动态/背水修法只改 `L.budget/L.depth` 与背水候选选择；预想期间 ctl 覆盖 deadline/nodeCap。
- 普通人机不传 maxMs，动态不会被砍；开计时/联机替补 AI 时按钟保护（main.js 原逻辑）。
- 本分支另含 main.js“复制对局文本”兜底修复（浏览器拦截自动复制时弹导出框），只影响 UI。
