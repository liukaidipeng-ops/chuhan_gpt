## 3. 工作流

### 3.1 输入
1. **Ham 的实战对局**：游戏里「保存 → 发给数值部」上传到 `liukaidipeng-ops/chuhan_gpt` 的工单（标签 `对局`；旧的在 `chuhan_v01`）。用 `tools/review/decode_issue.js` 还原，`tools/review/review.js` 按导出的版本号找到当时那份引擎和电脑复盘。截至 10-17 有 #13–#17 五局（霸王执楚，Ham 执汉全胜）。
2. **象棋Balance 转来的败局样本**：对打里电脑输掉的局、考卷不过的局面。
3. **Ham 口头说的想法**：“我觉得这里有个套路”。

### 3.2 每局对局的流程（收单 → 一页纸复盘）
1. 收单：在工单里回一句“战术部门已收，在复盘”（结尾带 Claude Code 署名）。
2. 用当时版本重放整局，核对每一步合法、终局一致；重放不了就写明原因（规则改过的老局）。
3. 标关键回合：局面分一步掉 2 分以上、Ham 悔棋集中、电脑没料到对方升级 / 技能、决定胜负的那一手。
4. 每个关键回合写一行：发生了什么 → 属于十级表哪一级的能力 → 是“已有战术又出现”还是“新候选”。
5. 交**一页纸复盘**：结论先行，最多一屏手机能看完；细节放附录。

### 3.3 一条战术的流程（候选 → 成立 → 入卷）
1. **候选**：至少有一局实战、或一次对打里出现；写清楚局面条件。
2. **验证**（门槛见第 4 节），定性为下面四种之一：
   - **强制组合**：对方怎么应都挡不住（在验证的步数内）；
   - **诱骗陷阱**：对方不防就中，防得住（写出最强反制）；
   - **控制窗口**：一段时间内的优势（例如四面楚歌期间），不一定直接赢；
   - **长计划**：多回合的布置（九级用）。
3. **写战术卡**（编号 T1、T2…，接着手册已有的 T1–T5 往下编），收进《机制战术手册》新版本。
4. **出考题规格**：会用题 + 会防题，各写局面、标准答案、判卷方式（必须走某步 / 别走那步 / 走完对方深搜找不到必胜 / 走完没有一步杀），标明等级。写进交付单交象棋Balance。
5. 象棋Balance 入卷、跑 `--lint` 和 `--verify`，结果回给战术部门；不同意的题两边对，对不上交 Ham 裁决。

## 4. 战术成立的门槛

1. **冻结身份**：写明规则提交号、`rules.js` / `bingfa.js` / `bfai.js` 的散列和规则开关（照手册 v0.2 第 2 节）。规则一改，旧战术要重验。
2. **合法重放**：每一步用引擎实际走一遍，血量、军功、击杀和事件逐项对上。
3. **找最强反制**：对方每一手的合法应对都要枚举，至少验证到战术结束；找到能破的就写出来，定成“诱骗陷阱”，不能写成必胜。
4. **深搜复核**：用电脑长时间深搜（每步 ≥ 8 秒或固定层数）看一遍，深搜不同意的写明分歧。
5. **证据分三档**，报告里分开写：已证（重放过）、待验（有依据没验完）、推测。
6. **不夸大**：只说验证过的步数；“十步以后”这类说法要有对应的验证，否则不写。
