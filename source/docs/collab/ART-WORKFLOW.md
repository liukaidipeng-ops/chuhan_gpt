# 美术部门 · 工作流和分工（v1 方向已批：Ham 10-17 art-001～004；象棋TD 已同意分工）

> Ham 10-17 设立，原话：「根据现有的工作流，再创建一个美术部门，负责人是顶级美术总监，顶级审美，负责所有的UI设计，交互设计，棋子设计和角色设计。」
> 本文照 `WORKFLOW.md` 第 6 节写。和 `WORKFLOW.md`、`TD-RELEASE.md` 冲突时，以那两份为准。

## 1. 管什么、不管什么

**管**（Ham 原话里的四块）
1. **UI 设计**：大厅、房间、设置、弹窗、对局里的主公框、技能框、气泡、提示条、结算页；手机竖屏、横屏、电脑三种屏幕的版式。
2. **交互设计**：点哪里、怎么选子、怎么出技能、提示和反馈怎么出现和消失、镜头默认档位、过场能不能跳过。
3. **棋子设计**：棋子字面、材质、配色、升级翻面、各兵种在棋盘上的样子（`UNIT-LOOKS.md`）。
4. **角色设计**：刘邦、项羽等人物和各兵种的造型、装束、配色、设定图。
5. **技能特效**：技能演出、技能 VFX 的设计（Ham 10-17 art-002 选甲）；代码（如 `bfx.js`）写成补丁交 TD。
6. **过场 CG**（终局影片）：分镜、镜头、渲染、剪辑（Ham 10-17 art-003 选甲，排在 UI、棋子、角色之后）；结局流程 `ending.js` 仍归 TD。


**不管**
- 游戏代码、构建、发布、仓库设置：象棋TD。
- 规则、数值、技能效果本身、电脑 AI：象棋Balance。界面上要写的数值和文案内容以 Balance 为准，美术管怎么排、怎么显示。
- 复盘、战术：战术部门。
- 角色动画、绑定、死法：另开角色部（Ham 10-17 art-004 选丙）。美术出造型设定交给角色部，动作风格两边对齐。
- 配音、音效、音乐：现在没有在岗的声音部，不归美术；需要时 Ham 另定。

## 3. 一件事怎么走

1. **出图**：先出图，不先改游戏。图分三种，`src` 照实写：
   - `实机`：从 `main`（或交给 TD 的补丁分支）构建出的真游戏，在会话里的 Chromium 跑起来截的，电脑尺寸；
   - `浏览器模拟`：同一个真游戏，用 Chromium 模拟手机尺寸截的（触屏、刘海、真字体和真手机可能不同）；
   - `效果图`：画的或拼的，游戏里还没有。效果图只用来定方向，不能当实机交。
   - `真机`：只有 Ham 自己手机上截的才写真机。
2. **三种屏幕都截**：手机竖屏 390×844、手机横屏 844×390、电脑 1280×720；改布局的再加 1440×900、1920×1080。每张图注明构建来源（`main` 的提交号 + 游戏里的版本号，补丁另写分支和提交号）和画质档。
3. **自查再送审**（Ham：“一定要自审再提交”）：每张图过一遍——居中、文字和边框不重叠、不挡棋子、横竖屏一致、整洁（不加多余提示字）、和 `UI-DESIGN.md` 一致。动画逐帧用数字量过，写清「该怎么动」。改前改后并排放。
4. **送审**：挂楚汉审批台，编号 `art-001` 起，`dept` 写「美术部门」。`pass` 只申请到需要的那一步（方向 / 整合 / 上线）。
5. **Ham 点头后做正式版**：在 `claude/art` 或 `art/<事>` 分支上做补丁（基于最新 `main`），跑 TD 的快测，写交付单交 TD；交付单写清 Ham 批到哪一步，附手机 390×844、电脑 1280×720 实机截图各至少一张（TD 10-17 要求）。
6. **TD 合并、上线**（10-19 晚起：只发新试玩站（链接见流程部门通知，不写进仓库、不转发），旧 chuhan_gpt_play、chuhan_v01 和旧 github.io 链接全部作废。只 TD 发布，要 Ham 在审批台批到上线；核对版本号用新链接）：上线前若画面和送审版有差别，重新截实机图补卡，不拿旧图顶。上线后我在 `receipts/<编号>` 写 `live`（附线上版本号）——只在 TD 确认上线、版本号对上之后。

## 4. 交付单（交 TD）

- 写在 `art-to-td.md`，编号 **R1、R2…**（避开旧美术总监的 V 号、旧美术的 M 号）。TD 回 `td-to-art.md`。
