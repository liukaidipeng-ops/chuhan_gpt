# 审批台（通用模板）

给「一个人拍板、多个 Claude 会话当部门干活」的项目用的统一审核页面。所有部门要拍板人定的事（看的图和录屏、听的声音、文字选方案）都挂在这一页；拍板人点选后「全部提交」，页面替他发一条评论通知各部门，部门在卡上写回执。

2026-10-17 为楚汉三维象棋做的，Ham 用下来说好用，要求备份以便别的项目用。楚汉那份在用的页面：https://claude.ai/artifact/54kSdoofarWafayd9DUjou 。

## 目录

| 文件 | 是什么 |
|---|---|
| `index.html` | 通用模板。换项目只改文件开头的 `CONFIG`、`<title>`、`<h1>` |
| `chuhan/index.html` | 楚汉在用的那份（2026-10-17 版），出事可以照它恢复 |
| `chuhan/部门接入.md` | 部门怎么接入：卡片字段、答案、回执、撤回。**别的项目照抄，只换部门名** |
| `test/mock.js`、`test/run.js` | 不连真数据库的浏览器测试：点选、要改没写备注被拦、提交、通知文本、回执、撤回确认、改版后重新送审、部门统计 |

## 页面做什么

- **一件一张卡**：要定什么、要点、候选和基线版本、包含和不包含、已测和没测（没测的标红）、材料（图、视频、音频，标明来历：实机、录屏、真机、浏览器模拟、效果图、样片、小样；模拟类标黄）。
- **「通过」带范围**：卡上写 `pass`，取「方向」「整合」「上线」之一，按钮上直接写清批到哪一步。只有「上线」才能交 TD 上线。
- **点选**：通过 / 要改 / 暂缓；方案卡是选甲乙丙 / 都不合适 / 暂缓。选要改必须写备注。备注能附图、粘贴截图、在送审图上标注（画笔、框、箭头、裁剪）；试听、看片时能把时间点记进备注。
- **全部提交**：底部固定一条，显示已点选几件、共几件；只发一条通知，按部门分段。通知发不出去时如实显示，并给「复制摘要」按钮。
- **回执**：部门写 `ack` 之后才显示「✓ 已收到」；处理进度（在做、受阻、做完、已上线）显示在卡上。
- **撤回**：点「撤回」只展开确认框；点「确认撤回并通知」才撤回，并通知部门。
- **改版**：部门把 `rev` 加 1 重新送审，卡回到待批，标「第 N 版」，显示上一版拍板人选了什么；旧答案不带到新版。
- **部门页**：每个部门等批、批了没回执、在做、受阻、做完的件数，全部从数据算出来，不能手填。

## 新项目怎么搭（约 15 分钟）

1. 复制 `index.html`，改开头的 `CONFIG`（标题、拍板人称呼、部门顺序），再改 `<title>` 和 `<h1>`。
2. 用 Artifact 工具发布，`capabilities` 设为：
   ```json
   {"db":{"rules":[{"path":"","read":"view","write":"admin"}]},"user":{},"comments":{},"assets":{}}
   ```
   **谁发布，页面的评论通知就先到谁的会话**；其他部门会话用 `ArtifactComments` watch 这个地址后也能收到。
3. 用 `ArtifactData` 往 `depts/<英文 id>` 写部门：`{name: "部门名", note: "一句话"}`。**文档 id 只能用英文、数字和 `_ - . ~ : @ +`**，中文名放进 `name`。
4. 挂一张示例卡（`demo: true`），让拍板人点一次、提交一次，确认通知能到你的会话，再写一条回执，看页面亮「✓ 已收到」。
5. 把 `chuhan/部门接入.md` 改成新项目的部门名，发给每个部门会话，让它们：
   - watch 审批台；
   - 送审写 `items/<编号>`；
   - 读 `decisions/<编号>`；
   - 每件写 `receipts/<编号>` 回执；
   - 挂完卡用 `send_message` 告诉管审批台的会话。
6. 在项目的工作流文档里写明：要拍板的事一律挂审批台，不在聊天里问。
7. 可选：建一个每小时巡查的定时任务（下面有模板）。

## 每小时巡查（定时任务模板）

用 `create_trigger` 建在管审批台的会话上，`cron_expression: "0 * * * *"`。提示词照这个改：

```
【审批台巡查】查一遍审批台 <地址>：
1. 用 ArtifactData 读 items、decisions、receipts、meta/push。
2. 算出待批的件（state 是 open，且没有当前版本的决定），跟 meta/push 的 pushed 比；有没提醒过的新件，就在对话里写一行「审批台有 N 件新件等你批：部门A 2、部门B 1」，并把 id 记进 pushed。
3. 拍板人批了（或撤回了）超过 30 分钟、部门还没写回执的：用 send_message 催出题部门（列出各部门 session id），记进 nudged，不重复催；超过 2 小时还没有，就在对话里告诉拍板人。
4. 没有新件、也没有超时，就什么都不说。
```

## 踩过的坑（楚汉 2026-10-10～17）

- **通知只认「页面替拍板人发评论给 Claude」**（`comments.sendToClaude`）。门铃（`fire_trigger` / `update_trigger`）时好时坏，页面也不知道送没送到。评论发不出去时，页面要如实写「没通知到」，不能显示「已通知」。
- **手机推送**（`PushNotification`）实测两次都没收到，拍板人开着对话时也会被系统跳过。不要把它当唯一提醒，改成在对话里提醒加每小时巡查。
- **时间要照实际时间写**：部门会话写回执、建卡时容易写成「将来」的时间。让它们用 `date -u +%Y-%m-%dT%H:%M:%SZ` 取当前时间。
- **回执要晚于决定**：`ack.at` 早于决定的 `at`，页面当作没收到。拍板人改了再交，部门要重写回执。
- **`[hidden]` 要自己补一条 `display:none !important`**，否则弹层的 `display: grid` 会盖过 `hidden`，挡住整页的点击。
- **推共享分支、申请仓库推送权限、新建仓库都可能被会话的自动权限检查拦下**：拍板人在那个会话的聊天里明确说一句允许，一般就能过；新建仓库目前会被 GitHub 拒（403）。
- **部门会话建的时候要挂仓库**（`create_session` 的 `source_url`），不然它要自己 `add_repo`，还可能只拿到只读权限。
- 别的账号发布的审批台，本会话用 Artifact 工具读会返回 404。要参考它的源码，就去仓库里找。

## 数据结构

见 `chuhan/部门接入.md`。集合有：`items`（卡片）、`decisions`（拍板人的决定和历史，提交时冻结一份快照 `snap`）、`receipts`（部门回执和进度）、`notices`（每次通知的结果）、`depts`（部门名和一句话说明）、`meta/push`（巡查记录）。
