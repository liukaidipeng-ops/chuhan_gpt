## 3. 设计、技术标准与验收

### 角色和动画

- 汉朱、楚墨；正常棋盘视角下兵种剪影要可辨。模型送审必须正、侧、背三面，并有棋盘尺度对照。只看近景不足以确认穿模、遮挡和邻格占用。
- 兵卒保留乙「盔胄对巾帻」：汉铁盔红缨、红袍、方盾、矛；楚巾帻、无袖皮背心、裹腿、圆盾和戟。一级1v1、二级2v2配合、三级3v3阵型、四级3v3金甲斩马刀。
- 动作需要攻防来回、清楚蓄力与受力、盾面朝向正确、握矛位置动态调整，不反关节、不穿盾穿身。扣血与吃子分清：吃子守方全死，击飞和概率断肢在运行时结算，不能固定播放同一种结果。
- 单人骨架有两节膝肘反解；姿势包含胯、上身、头、脚落点、握矛点与盾向。对打代码已有 SkinnedMesh/Skeleton，不能把旧通用 Troop 无膝肘的限制误当成当前 Duel 的限制。
- 用实际游戏默认1.5倍速评节奏；char-026最终顿足时矛、刀、盾都随身体运动。保底版获批后不要重启已叫停的 soldier2/duel5 路线。

### 接口与资源

- TigerHD.make(side,{lv})：group头朝+X、脚底y=0，小队管理缩放；speed/pounceK/roarK/dead/deadSide；blast/rend/fall({dir,power})返回Promise。文臣攻击时端坐，节杖稳定，不做近战。
- JumaWall.make(side,n)：group/pieces/update/shake/shatter/reset/dispose；+z朝来敌，棋盘单位。扣血晃动不碎，吃子彻底碎掉。
- ElephantLV.make(side,{lv,plan:'b'})：保留原象对象接口，新增lvScale/topY。技能等级每级一只，不再叠加象数；普通模式沿原造型。旗杆当前根部为topY×EL×lvScale−0.28，塔高变更必须复核。
- 当前 Duel.play({lv,kill,att,speed,onEvent,parent}) 懒创建独立画布和渲染器；stop停止，engine.length查询时长。onEvent为block/parry/clank/hit/kill/thud/dust，声音按真实事件触发，不能只抄旧M27秒表。
- 共享几何需keep保护，克隆避免Object3D.clone(true)序列化userData；贴图toon使用unique:true；原型随机可复现。主场景版需要明确对象归属、停止与清理，不能误释放共享棋盘资源。

### 性能与验收方法

- 历史虎骑预算：含描边高≤65000面、中≤40000面；首次≤300ms、克隆≤5ms、≤70网格、贴图边长≤1024且≤10张。这是旧虎骑标准，不应不加区分套到新火象。
- 火象最新p-06记录要求每只≤25000面、≤30次绘制，并希望比较5000/10000/25000三档；三档图尚待制作。M33的四级11个可见网格、17次含影绘制是历史报告，H37实测约+18，测量口径必须标明，本轮未复测。
- 未来H38验收矩阵：1～4级×扣血/吃子×汉楚攻方；cine/std在主场景、low不演；棋子/兵种显示、相邻子遮挡、棋盘边缘、暂停停止、连续重复播放、1.5倍速与其它倍速；血量、棋子收场、回合推进和声音不重复。
- cine由TD现有Fx.shot接镜头，std不改变镜头；图片加真实棋盘连续录像。逐帧检测落脚、武器接触、盾面和模型衔接，前后位置/朝向/大小应连续。移动端、低画质、未录场景必须写明未测。
- 固定步长工具可参考duel-mod/test.py和交接所列geo.py/vid.py；脚本本身不是通过证据。后续只在独立工作副本运行，完成构建和与改动相关的检查后再交付。
