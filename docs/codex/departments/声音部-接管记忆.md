## 3. 技术标准与验收方法

- 配音分写实 MiniMax（默认）、原版 Kokoro（保留选项）；技能名将句可回退写实包。字幕先核对 real.json/text 与 lines.json 的模式差异。
- 通用配音入库 pack.py 使用 32 kHz、单声道、56 kbps；−17.4 dB 是代码按 RMS 归一化的目标，不误写为 LUFS。喃喃 mkmuse.py 使用 ebur128 测量，刘邦约 −20.3 LUFS、项羽约 −19.2 LUFS；刘邦混响 wet=0.25、rt=1.4。
- 音效标准在工作流中为 22.05 kHz 单声道，manifest 记录 f/dur/src；音效许可限历史规范列出的 CC0、CC BY 3.0、CC BY-SA 3.0，并核对署名。未重新审查全部素材许可。
- 大音频外置 sfx.bin、voice-real.bin、voice-bf.bin、voice-orig.bin、music-war.mp3；不能因新声音扩大首屏内嵌负担。工作流旧包大小只作历史基线。
- 演出速度与真实音频时长须换算；优先绑定动画事件。block 的 0.23 秒提前量在函数内处理；S3 的箭、击中、扑起、撞上不得再凭旧分镜硬塞时点。
- S6 的 onEvent → Sfx.B.duel(kind)，七类事件 parry/block/clank/hit/kill/thud/dust；同 kind 60 ms 去重，duelDone 防棋盘扣血再响盾挡。
- 开场 EndTunes 是 const 全局，必须 typeof 判断；open 不停止背景乐。仅单调声音函数不构成验收，必须通过真实开局/动画路径确认调用发生。
- 后续获具体实施任务后：保存样片版本与批准映射，核对字幕、包归属、许可、音量峰值和时序；运行适用构建与测试，实际浏览器检查真实触发、快慢演出、重叠和加载缺失行为，手机音频解锁/静音开关及性能影响。本次未执行这些运行验收。
