## 3. 技术标准与验收方法

历史批准预算：局内整帧 ≤400 次绘制（目标250）、≤40万三角形；普通单角色 ≤5000 三角形、≤8次绘制，蒙皮1–3网格、每网格≤40骨骼、贴图≤512。两兵对打模块 ≤3万三角形、≤30次绘制；着色器提前准备，演出完释放资源。p-06 对象另开例外：每只≤2.5万面、≤30次绘制，其余兵种不变。预算是保守工程目标，不是真机实测上限。

CG 历史预算：整帧≤200绘制、≤60万三角形；主角≤3万面、≤6网格、≤60骨骼，贴图≤1024（主角脸可一张2048）。每段压缩后≤3MB，独立文件按需下载、有进度、失败能跳过，过场时停棋盘渲染。Q1 的 H.264、720p/30fps、播放兼容性与颗粒层建议是历史技术建议，非本轮兼容性认证，非逐条用户批准。

测量须注明提交、尺寸、画质、像素比、CPU降速、场景、采样时长、影子是否计入、真实渲染或计数替代。旧环境为390×844、DPR3、中画质、CPU降速4倍、SwiftShader；软件渲染不能推算手机GPU帧率、温度或电量。bench 的 stub 模式每15次仍真画一次，并非完全不渲染。应分别报告真实 drawN、屏幕刷新、draw calls、三角形、长任务、首屏大小/加载时间。模型隐藏网格数不可冒充绘制次数。

P6 后续验收矩阵：省电开/关；静止、触摸、走子/镜头/演出；60/90/120/144Hz；静止转活动及后台恢复。静止保持约15帧，活动省电约60帧（统计窗口可有±1），关省电不受此限；时间推进、自动降画质统计不误判。读过的补丁带2ms容差，不能仅凭文字断言任意刷新抖动均严格≤60，需实际验证节拍与长暂停恢复。

代码交付需对目标基线 git apply --check、构建及适用回归。旧交付说8组测试通过（rules、engine、jieqi、bingfa、beishui、r6、bfai、bfai.policy），本轮未重跑，长AI测试不可借此自动启动。画面同机位同时间对比，并考虑随机动画噪声。内存需多局资源回收对照，首局堆下降不能证明长局无泄漏。
